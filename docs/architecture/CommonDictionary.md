# Common Dictionary

## 2026-08-19 DataTables server-side POST 요청 계약

- `createDataTable()`은 `serverSide: true`일 때 DataTables의 `columns[]`, `order[]`, `search`, `draw`, `start`, `length`와 화면 검색조건을 공용 AJAX의 form-urlencoded POST body로 전송한다. 화면별 method 지정은 금지하며, 일반 client-side 목록은 기존 GET을 유지한다.
- `DataTableRequestHelper::input()`은 짧은 URL scope와 PHP가 파싱한 POST body를 병합하되 body를 우선한다. server-side 목록 Controller의 단일 입력 경계이며 JSON 재파싱이나 GET 실패 후 POST 재시도를 만들지 않는다.
- 대형 목록 문제를 웹서버 URI 제한 확대로 해결하지 않는다. 신규 server-side 목록은 공용 계약을 사용하고 48열 이상 payload의 HTTP 414 회귀를 검사한다. 조회용 POST는 상태 변경이 아니며 저장·수정·삭제 API와 분리한다.

## 2026-08-13 DataTable 레이아웃 폭 안정화

- `bindDataTableContainerResize(table)`: DataTable이 실제 배치된 폭 Scope를 `ResizeObserver`로 관찰하고, 연속 폭 변경이 120ms 동안 안정된 뒤 `refreshDataTableLayout()`을 한 번만 실행한다. 좌측 사이드바 전환 완료 시 `sidebar:toggled` 이벤트로 최종 폭을 즉시 재검증한다. `window.resize`, `visualViewport.resize`, 사이드바 직접 `columns.adjust()`를 중복 실행하지 않는다.
- `sidebar.js`: 사이드바 전환 중 테이블을 직접 다시 그리거나 가상 `window.resize`를 발생시키지 않고, 전환 완료 후 `sidebar:toggled`만 발행한다. 사이드바와 핸들은 합성 레이어의 `transform`만 애니메이션하며, 본문 `width`/`margin-left`는 한 번에 변경해 큰 테이블의 프레임별 reflow를 방지한다.

## 2026-08-12 급여(신고) 외부 원본키

- `EvidenceExternalKeyService`: `PAYROLL_REPORT`는 `source_regular_employment_income_id`를 안정적인 원본 식별값으로 사용한다. 상용근로소득 Header 1건과 급여(신고) 증빙 1건의 멱등 생성을 보장하며 생성·수정 시각이나 내부 증빙 ID는 키에 사용하지 않는다.

## Route 권한 별칭

- Route 메타의 `permission_key`는 Route 고유 `key`와 실제 검사할 권한 키가 달라야 할 때 사용한다.
- `Router`는 별칭 Route를 독립 권한으로 등록하지 않고, `PermissionMiddleware`는 `permission_key`를 우선 검사한다.

## 2026-08-11 설정 기준관리 Navigation

- 설정 공용 카테고리·탭 UI를 재사용해 `기준관리` 아래에 `코드`, `법정기준` 탭을 순서대로 표시한다. 코드관리 페이지의 업무명·제목·권한명은 `코드관리`를 유지하며, 기존 `system/codes.php`, `system/code.js`, `system/code.css` 단일 구현과 기존 `code.*` 권한 및 `/api/settings/system/code/*` API를 그대로 사용한다.

## 2026-08-11 법정기준 DB Metadata UI 계약

- 법정기준 물리 컬럼의 기본 UI 계약은 공용 `DataTableColumnMetaService`가 DB `COLUMN_COMMENT`를 `label`로, `IS_NULLABLE=NO`를 `required=true`로 변환해 만든다. `id`, Actor·생성 컬럼, FK, 원본 JSON·파일 내부 컬럼은 사용자 입력 대상이 아니므로 기본 숨김 처리한다.
- DataTable과 Modal은 동일 메타데이터 및 저장된 `columnDisplayName`/`columnRequirementPolicy`를 소비한다. Modal의 필수구분은 `required` 빨간 별표, `optional` 파란 별표, `none` 미표시로 렌더링한다. 별도 Table Setting이 없는 관련근거 입력은 `system_statutory_standard_sources`의 DB COMMENT를 라벨로 사용하고 `IS_NULLABLE=NO`는 빨간 필수 별표, `YES`는 파란 선택 별표로 표시한다. `value_data` 내부 동적 필드는 물리 컬럼이 아니므로 `STATUTORY_STANDARD_TYPE.extra_data`의 `name`/`required`를 SSOT로 사용한다.
- 법정기준 DataTable은 공용 목록형 기본 도구 순서(검색, 선택행 상·하 이동, 복사, 삭제, 페이지 버튼, 페이지당 건수, 테이블설정)를 사용한다. 이 화면에서 미적용인 휴지통·엑셀 버튼은 만들지 않으며, 좌측 가상열은 선택 체크박스와 드래그 핸들, 우측 가상열은 관리 버튼으로 고정한다. 공용 열표시와 Table Setting을 모두 사용한다.
- 법정기준 등록·상세 Modal은 거래입력 Modal의 헤더, 카드, 간격, 반응형 레이아웃을 기준으로 한다. 각 카드 제목 바로 아래에는 공용 DB Metadata의 `table_comment(table_name)`을 표시하며, 시스템 자동처리 컬럼은 마지막 `시스템 처리 정보` 카드에서 기본 접힘 상태의 읽기 전용 값으로만 노출한다.
- `MatrixEditor`는 Dynamic Structured Field의 `type=matrix` 공용 Adapter다. 렌더링·편집·선택·컬럼폭·Formatter·스크롤은 `createHtmlGrid`와 `.html-grid-host`가 담당하고, Matrix Editor는 Schema, Parser, Validation 및 저장 변환만 담당한다. `rate` 열은 공용 `rateToPercent`/`percentToRate` 계약으로 저장 ratio를 화면 percent로 변환하고 공용 HTML Grid percent Formatter에 `inputScale=percent`를 전달한다. 화면의 `95%`는 화면단위 한계 `0~100`으로 먼저 검증한 뒤 저장 직전에 `0.95`로 정규화하며, 재조회 시 다시 `95%`가 된다. nullable 마지막 종료구간은 `null`을 유지한다. `parseMatrixPasteInChunks`는 대량 행을 75행 단위로 처리하며 전체 성공 후에만 Grid를 교체한다. `createMatrixGridRows`는 flat row를 HTML Grid 표준으로 변환하고 `buildMatrixObjectValue`는 동적 Map을 조립한다. 업무 API나 DB는 직접 호출하지 않는다.

- 같은 역할이 있으면 기존 함수를 callback 또는 Service 의존성으로 주입한다.
- 함수 시그니처를 변경할 때는 이 문서를 먼저 갱신한다.
