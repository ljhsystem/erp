# Common Dictionary

## API 구조화 오류

- `Core\Helpers\ApiErrorResponseHelper::payload()`: 공용 API 실패 응답의 `success`, `error`, `reason_code`, `message`, `field_errors`, `missing_inputs`, `invalid_workdays` 최소 계약을 생성한다.
- `Core\Helpers\ApiErrorResponseHelper::exception()`: Validation/Request key 오류를 구조화하고 PDO·SQLSTATE 원문은 표준 사용자 메시지로 차단한다.

## Employment-contract project reference metadata

- The employment-contract DataTable renders `project_name` through the physical TableSettings key `project_id`. Its default display name is `특정 프로젝트`, while a saved TableSettings display name continues to control both the list header and matching Modal/Form label.

## DataTableFormSettings modal boundary

- `createDataTableFormSettings()` reuses TableSettings display names and requirement policies for Modal/Form labels and validation. A page may supply the current DataTable `stateProvider`; live state takes precedence over cached storage so a just-saved use-column name and requirement policy are reflected immediately. DB nullability supplies the TableSettings default, while a saved `required`, `optional`, or `none` policy controls the modal marker and HTML `required` state.
- DataTable `visibleColumns` and `columnOrder` never hide, show, or rearrange Modal/Form fields. Modal/Form visibility and layout remain owned by its markup and domain business policy.

## 2026-08-19 DataTables server-side POST 요청 계약

- `createDataTable()`은 `serverSide: true`일 때 DataTables의 `columns[]`, `order[]`, `search`, `draw`, `start`, `length`와 화면 검색조건을 공용 AJAX의 form-urlencoded POST body로 전송한다. 화면별 method 지정은 금지하며, 일반 client-side 목록은 기존 GET을 유지한다.
- 공용 `createDataTable()`의 server-side 목록은 DataTables 고유 전역검색을 항상 활성화하고 `search[value]`를 서버로 전달한다. 화면별 `SearchForm`은 날짜·필드 조건을 추가하는 보조기능이며 고유 전역검색을 대체하거나 숨기지 않는다. `ajaxData()`가 업무조건 객체를 반환해도 공용 Adapter가 원본 `draw/start/length/columns/order/search` 요청과 병합하며, 셀 클릭으로 조건검색 입력을 자동 변경하는 `cellSearchFill`은 명시적으로 요청한 화면에서만 사용한다.
- `DataTableRequestHelper::input()`은 짧은 URL scope와 PHP가 파싱한 POST body를 병합하되 body를 우선한다. server-side 목록 Controller의 단일 입력 경계이며 JSON 재파싱이나 GET 실패 후 POST 재시도를 만들지 않는다.
- 대형 목록 문제를 웹서버 URI 제한 확대로 해결하지 않는다. 신규 server-side 목록은 공용 계약을 사용하고 48열 이상 payload의 HTTP 414 회귀를 검사한다. 조회용 POST는 상태 변경이 아니며 저장·수정·삭제 API와 분리한다.

## 2026-08-13 DataTable 레이아웃 폭 안정화

- `bindDataTableContainerResize(table)`: DataTable이 실제 배치된 폭 Scope를 `ResizeObserver`로 관찰하고, 연속 폭 변경이 120ms 동안 안정된 뒤 `refreshDataTableLayout()`을 한 번만 실행한다. 좌측 사이드바 전환 완료 시 `sidebar:toggled` 이벤트로 최종 폭을 즉시 재검증한다. `window.resize`, `visualViewport.resize`, 사이드바 직접 `columns.adjust()`를 중복 실행하지 않는다.
- `sidebar.js`: 사이드바 전환 중 테이블을 직접 다시 그리거나 가상 `window.resize`를 발생시키지 않고, 전환 완료 후 `sidebar:toggled`만 발행한다. 사이드바와 핸들은 합성 레이어의 `transform`만 애니메이션하며, 본문 `width`/`margin-left`는 한 번에 변경해 큰 테이블의 프레임별 reflow를 방지한다.

## Route 권한 별칭

- Route 메타의 `permission_key`는 Route 고유 `key`와 실제 검사할 권한 키가 달라야 할 때 사용한다.
- `Router`는 별칭 Route의 고유 `key`를 독립 권한으로 만들지 않고 실제 검사 대상인 `permission_key`를 Registry에 등록한다. `PermissionMiddleware`도 같은 `permission_key`를 우선 검사하므로 자동동기화·부여목록·실제 접근판정이 동일한 Key를 사용한다.

## 2026-08-11 법정기준 DB Metadata UI 계약

- `DataTableColumnMetaService`의 가상 Projection metadata는 실제 API `column_key`, `source_type=VIRTUAL`, 표시명·자료형·기본노출·순서·정렬·검색·숨김·너비·정렬방향·Formatter·설명을 공용 TableSettings에 제공하며 Modal 입력필드를 만들지 않는다. 법정기준 `period_status`는 `effective_from`, `effective_to`, 서버 회사 업무일 기준 판정 결과만 표시하고 DB에 저장하지 않는다.
- `StatutoryStandardPeriodStatusProjection::displayOptions()`는 적용상태 배지의 서버 표시계약을 제공한다. 활성 `STATUTORY_STANDARD_PERIOD_STATUS` 코드명이 있으면 이를 우선하고, 코드 Seed가 아직 적용되지 않은 환경에서는 동일한 `SCHEDULED/CURRENT/ENDED` 세 코드에 한해 표준 한글명을 반환해 영문 코드 노출을 막는다. JS는 상태명을 하드코딩하거나 재판정하지 않는다.

- 법정기준 물리 컬럼의 기본 UI 계약은 공용 `DataTableColumnMetaService`가 DB `COLUMN_COMMENT`를 `label`로, `IS_NULLABLE=NO`를 `required=true`로 변환해 만든다. `id`, Actor·생성 컬럼, FK, 원본 JSON·파일 내부 컬럼은 사용자 입력 대상이 아니므로 기본 숨김 처리한다.
- 보험 법정기준 모달은 `STATUTORY_STANDARD_TYPE.extra_data.component_templates`의 Dimension과 `group_code/group_name/value_path`로 공용 기준값 카드를 구성한다. 목록 TableSettings와 Modal 입력 노출은 분리하며 원시 JSON 편집기는 사용하지 않는다.
- 법정기준 목록의 `value_summary`는 `value_data`를 대체하지 않는 가상컬럼이다. 공용 TableSettings에는 `기준값`으로 등록하되 Modal 입력필드를 생성하지 않고, 금액·요율·Matrix·가입자격 Summary 표시계약을 정책 구성요소에 따라 구분한다.
- 법정기준 DataTable의 `value_summary`는 `settingsVirtualType=calculated`인 계산 가상컬럼이며 renderer가 현재 서버 행의 `row.value_summary`를 명시적으로 읽는다. DataTable의 가상·숨김 컬럼 삽입이나 TableSettings 순서변경 후에도 문자열 data-path의 위치 추론에 의존하지 않는다.
- 공용 TableSettings는 기존 저장계약의 컬럼 목록 어디에도 없던 신규 기본노출 컬럼을 최초 병합 시 `visibleColumns`에 추가한다. 저장계약에 이미 존재하지만 사용자가 숨긴 컬럼은 다시 노출하지 않는다. 이 계약으로 신규 가상 Projection도 기존 사용자 컬럼 순서·표시명·숨김 설정을 초기화하지 않고 도입한다.
- 보험 Header 종속 선택은 같은 `component_templates`에 존재하는 값만 노출한다. 단일 선택값은 잠그되 FormData에는 명시적으로 포함하고, 목록·상세는 `기관 · 구성요소/고용형태 · Scope` 조합명을 표시한다.
- 공용 TableSettings는 물리컬럼 표시명이 과거 빈 DB COMMENT로 인해 원본 key와 동일하게 저장된 경우에만 현재 DB COMMENT 기본명으로 동기화한다. 원본 key와 다른 사용자 지정 표시명은 보존하며 설정행을 삭제하거나 초기화하지 않는다. 컬럼 기본값 복원은 클릭 시 현재 DB metadata를 다시 조회하고, 물리 원본 컬럼명은 `COLUMN_NAME`, 순서는 `ORDINAL_POSITION`, 사용컬럼명은 `COLUMN_COMMENT`(비어 있으면 `COLUMN_NAME`), 필수 기본값은 `IS_NULLABLE`만을 따른다.
- DataTable과 Modal은 동일 메타데이터 및 저장된 `columnDisplayName`/`columnRequirementPolicy`를 소비한다. Modal의 필수구분은 `required` 빨간 별표, `optional` 파란 별표, `none` 미표시로 렌더링한다. 별도 Table Setting이 없는 관련근거 입력은 `system_statutory_standard_sources`의 DB COMMENT를 라벨로 사용하고 `IS_NULLABLE=NO`는 빨간 필수 별표, `YES`는 파란 선택 별표로 표시한다. `value_data` 내부 동적 필드는 물리 컬럼이 아니므로 `STATUTORY_STANDARD_TYPE.extra_data`의 `name`/`required`를 SSOT로 사용한다.
- 법정기준 DataTable은 공용 목록형 기본 도구 순서(검색, 선택행 상·하 이동, 복사, 삭제, 페이지 버튼, 페이지당 건수, 테이블설정)를 사용한다. 이 화면에서 미적용인 휴지통·엑셀 버튼은 만들지 않으며, 좌측 가상열은 선택 체크박스와 드래그 핸들, 우측 가상열은 관리 버튼으로 고정한다. 공용 열표시와 Table Setting을 모두 사용한다.
- 법정기준 등록·상세 Modal은 거래입력 Modal의 헤더, 카드, 간격, 반응형 레이아웃을 기준으로 한다. 각 카드 제목 바로 아래에는 공용 DB Metadata의 `table_comment(table_name)`을 표시하며, 시스템 자동처리 컬럼은 마지막 `시스템 처리 정보` 카드에서 기본 접힘 상태의 읽기 전용 값으로만 노출한다.
- `MatrixEditor`는 Dynamic Structured Field의 `type=matrix` 공용 Adapter다. 렌더링·편집·선택·컬럼폭·Formatter·스크롤은 `createHtmlGrid`와 `.html-grid-host`가 담당하고, Matrix Editor는 Schema, Parser, Validation 및 저장 변환만 담당한다. `rate` 열은 공용 `rateToPercent`/`percentToRate` 계약으로 저장 ratio를 화면 percent로 변환하고 공용 HTML Grid percent Formatter에 `inputScale=percent`를 전달한다. 화면의 `95%`는 화면단위 한계 `0~100`으로 먼저 검증한 뒤 저장 직전에 `0.95`로 정규화하며, 재조회 시 다시 `95%`가 된다. nullable 마지막 종료구간은 `null`을 유지한다. `parseMatrixPasteInChunks`는 대량 행을 75행 단위로 처리하며 전체 성공 후에만 Grid를 교체한다. `createMatrixGridRows`는 flat row를 HTML Grid 표준으로 변환하고 `buildMatrixObjectValue`는 동적 Map을 조립한다. 업무 API나 DB는 직접 호출하지 않는다.

| DataTableSettings | Shared DataTable settings controller for persisted TABLE state (`visibleColumns`, `columnOrder`, `requiredColumns`, `columnDisplayName`, `columnRequirementPolicy`) and separate VIEW state (`columnWidths`, `searchFormExpanded`, `sortSettings`, `pageLength`). Every row exposed in TableSettings is movable, including physical, calculated/other virtual, and `__select`/`__reorder`/`__actions` system virtual columns; applying saved state never forces a system column back to a fixed position. ## `confirmDialog`

- 경로: `public/assets/js/common/confirm-dialog.js`
- Bootstrap Modal 기반 비동기 공용 확인 Dialog다. 업무 API를 호출하지 않고 제목·안내문·진행/취소 문구와 확인 버튼 스타일만 입력받아 `Promise<boolean>`을 반환한다.
- 동시에 둘 이상의 확인 Dialog를 생성하지 않으며 닫힌 뒤 DOM과 Bootstrap 인스턴스를 제거한다.
- 분개규칙 목록은 공용 `SearchForm`, `createDataTable`, Table Setting, Row Reorder, Trash Manager와 Actor 표시를 재사용한다. 전용 Excel Manager는 사용하지 않으며, `sort_no` 변경은 동일 점수 Rule의 추천순위에도 영향을 줄 수 있음을 화면 정책으로 취급한다.

### DataTableSettings 원본 표시

- 복합 metadata의 원본컬럼명은 `테이블번호-원본테이블 내부순번.컬럼명` 형식으로 표시한다. 예를 들어 첫 번째 등록 테이블의 DB `ORDINAL_POSITION=7`인 `memo`는 `1-7.memo`다. 별도 순번 열은 등록된 모든 테이블을 연결한 누적 `ordinal_position`을 계속 표시하므로 사용자는 도메인 전체 순서와 원본 테이블 내부 순서를 동시에 확인할 수 있다. 문자열 자체나 저장 key에 접두사를 삽입하지 않고 TableSettings renderer에서만 조합한다.
- 원본컬럼명 줄바꿈 시 `테이블번호-원본순번.` 접두사만 첫 줄에 고립되거나 `5-`와 `7.` 사이가 분리되지 않도록 접두사와 컬럼명의 첫 글자를 하나의 `nowrap` 단위로 렌더링한다. 나머지 컬럼명에만 `overflow-wrap:anywhere`를 적용해 `5-7.a` 다음의 긴 `ssignment_...` 부분이 셀 안에서 자연스럽게 이어서 줄바꿈되도록 한다. 전체 원본 문자열은 title과 화면 본문에 생략 없이 유지한다.

- 공용 기본값과 기본값 복원은 `__select → __reorder → DB 기본순서의 본문컬럼 → __actions` 순서를 사용한다. 페이지가 `__reorder`를 선언하지 않은 경우에도 공용 설정이 실제 시스템 가상컬럼을 보강하며, 보기 스위치를 켜면 DataTable에 드래그핸들 열을 표시한다. 페이지가 RowReorder를 활성화하지 않은 경우 핸들은 표시만 하고 데이터 행 순서를 변경하지 않는다.
- 공용 모달 제목은 `Table Settings`이며, 하단에 원본 테이블을 최초 등장 순서대로 `번호. 테이블명 / 테이블 코멘트 (컬럼 수)` 형식의 줄바꿈 목록으로 표시한다.
- 원본 테이블과 컬럼 수는 제목 하단 요약에서 확인하며, 목록은 DB `source_ordinal_position`을 표시하는 순번과 원본컬럼명 전체 문자열을 서로 다른 열에 표시한다. 사용자 행 정렬은 DB 원본 순번을 변경하지 않으며 저장 key와 DB metadata 계약을 유지한다.
- 컬럼 목록은 프로젝트 범용 공용 `createHtmlGrid()`와 `.html-grid-host`를 사용하며, TableSettings Adapter가 선택·핸들·DB 원본순번·원본컬럼명·사용명·필수구분·보기 schema/editor와 기존 저장계약을 연결한다. 가상컬럼도 순서변경 선택 체크는 가능하지만 기존 `movable: false` 위치보호 정책은 유지한다. 공용 `html-grid.css`는 전역 레이아웃에서 한 번 로드한다.
- 혼합형 목록의 설정 대상 가상컬럼은 공용 컬럼 정의의 `settingsVirtualType`으로 분류한다. `system`은 연한 danger Badge와 gear 아이콘, `calculated`는 연한 success Badge와 calculator 아이콘, 아직 정의되지 않은 기타 유형은 중립 Badge와 puzzle 아이콘을 사용한다. `computed`·`formula`는 `calculated`, 기존 `__select`·`__reorder`·`__actions`는 선언 없이 `system`으로 정규화한다. 모든 가상컬럼은 업무컬럼 순번 계산에서 제외하며 사용자 저장 key 계약은 유지한다.
- metadata domain이 있는 혼합형 목록에서는 metadata key와 매칭되는 컬럼, 예약 시스템 가상컬럼, `settingsVirtualType`을 명시한 가상컬럼만 TableSettings 대상으로 인정한다. JOIN 참조값·별칭·Projection은 화면에 표시되더라도 명시적 가상유형이 없으면 설정 및 사용자 저장 대상에서 제외한다. 물리 테이블 자체에 같은 이름의 컬럼이 존재해 metadata key가 매칭되는 경우에는 정상 물리컬럼으로 포함한다.
- 공용 Adapter의 내부 정규화 결과인 `__dtVirtualType`은 페이지가 선언한 `settingsVirtualType`으로 간주하지 않는다. Modal 진입 시 컬럼을 재정규화해도 내부 기본값 `other`가 명시적 가상컬럼으로 승격되어 JOIN·요약·대표 Projection이 TableSettings에 다시 나타나면 안 된다.
- TABLE 저장상태 정규화의 available key도 `__dtSettingsConfigurable` 컬럼으로 제한한다. 이전 저장값에 남은 참조·Projection key는 `visibleColumns`·`columnOrder`뿐 아니라 `columnDisplayName`·`columnRequirementPolicy`에서도 제거하고 정규화된 상태를 기존 공용 저장소에 다시 반영한다.
- `html-grid-variant-settings`는 공용 HTML Grid의 설정형 화면 variant다. Core renderer를 변경하거나 복제하지 않고 46px header, 56px body row, 38px editor, 설정화면용 hover·selection·focus 외형을 제공한다. TableSettings는 이 variant로 전환 전 정보밀도와 여백을 유지한다.
- 설정형 Grid의 sticky header는 `border-collapse: separate`와 46px header row/cell 고정 높이를 사용해 스크롤 전후 높이와 경계선이 달라지지 않도록 한다. TableSettings toolbar도 최소 64px의 고정 flex item으로 유지해 header의 sticky top 기준이 변하지 않게 한다.
- TableSettings sticky top은 숨겨진 Modal에서 측정한 fallback 값을 확정값으로 사용하지 않는다. `shown.bs.modal` 이후 실제 toolbar 높이를 반영하고 `ResizeObserver`로 toolbar 줄바꿈·반응형 높이 변경을 추적해 header가 toolbar 아래로 들어가 잘리지 않도록 한다.
- TableSettings Modal의 body, settings shell, panel body, Grid scroll은 `min-height: 0` flex 체인으로 실제 가용 높이를 공유한다. Grid scroll은 viewport 상수로 높이를 추정하지 않으며 독립적으로 축소·스크롤되어 마지막 행이 Modal footer 뒤로 들어가지 않고 footer 상단까지 완전히 노출되어야 한다.
- TableSettings Modal header는 제목 아래 원본 테이블 목록의 줄 수와 관계없이 상단정렬하며 닫기 X는 `margin-left:auto`로 항상 header 우측 상단에 둔다. 긴 테이블 목록 높이를 기준으로 X를 세로 중앙정렬하지 않는다.
- 설정형 Grid는 별도 scroll shell 안에서 사용되므로 공용 기본 Grid의 마지막 셀 border 제거 규칙을 재정의해 마지막 header/body 셀의 우측 경계선을 유지한다. 이에 따라 TableSettings 보기 열 우측 테두리가 스크롤 끝에서 잘려 보이지 않는다.
- 공용 HTML Grid의 행 선택 체크박스는 `.html-grid-row-selection`에서 body font-size를 사용한다. 헤더 전체선택에도 같은 클래스를 적용해 12px header 글꼴의 `1em`을 상속받아 작아지지 않고 본문 체크박스와 동일한 크기를 유지한다.
- TableSettings 보기 스위치는 ON/OFF 상태 모두 2rem × 1rem의 동일한 트랙 크기를 유지하며 상태 변경 시 transform이나 flex 축소로 외곽 크기가 달라지지 않는다.
- 시스템 가상컬럼 `__select`, `__reorder`, `__actions`의 capability는 모든 공용 DataTable에서 동일하다. 기존 페이지 컬럼의 `no-colvis`나 선택기능 사용 여부와 관계없이 TableSettings의 보기와 너비는 항상 편집 가능하다. 반면 DB NULL 계약이 없는 시스템컬럼의 필수구분과 정렬/방향은 항상 비활성화한다. 시스템컬럼의 고정 위치정책과 실제 기능 지원 여부는 이 보기·너비 capability와 별도로 유지한다.
- 공용 TableSettings는 페이지 컬럼에 명시적 key가 없어도 선택 class, 드래그 class, `data:null + 제목 관리/수정`을 각각 기존 `__select`, `__reorder`, `__actions`로 먼저 정규화한 뒤 누락 placeholder를 보충한다. 따라서 페이지의 실제 관리컬럼과 공용 관리 placeholder가 중복되면 안 된다. `__actions`의 기본 사용컬럼명은 Bootstrap gear 아이콘 값이 아니라 한글 `관리`이며, 과거 자동 기본값 `bi bi-gear`·`bi bi-gear-fill`도 `관리`로 정규화한다. 사용자가 이후 명시적으로 지정한 다른 문자·아이콘 표시는 기존 지원을 유지한다.
- `defaultVisibleColumns`는 최초 사용자 설정이 없는 페이지의 DB 업무컬럼 초기 보기 목록이며 시스템 가상컬럼의 초기 보기를 덮어쓰지 않는다. `컬럼 기본값 복원`과 `보기 기본값 복원`은 모두 현재 `visibleColumns` 토글 상태를 보존한다. 증빙원본 공용 페이지는 유형별 `defaultVisibleColumns`나 전용 숨김 목록을 두지 않으며, 사용자가 보기 토글을 직접 저장한다.
- 공용 TableSettings UI는 TABLE의 표시·순서·사용컬럼명·필수구분과 VIEW의 `columnWidths`, `sortSettings`, `pageLength`, `searchFormExpanded`만 한 모달에서 편집한다. 보기 OFF 컬럼의 너비는 빈 값·비활성으로 표시하고 VIEW 너비 초안에서도 제거하며, 보기 ON 전환 시 컬럼 정의 너비 또는 공용 기본 너비를 초안에 채운다. 활성 너비는 spinner 없는 `◀ 숫자 ▶` 공용 제어로 1px씩 조절하며, 정렬은 컬럼 행의 DataTable 공용 삼각형을 순환한다. 모든 변경과 기본값 복원은 저장 전까지 모달 초안에만 머물고 저장 클릭 시 실제 DataTable과 기존 `setting_type=TABLE`·`setting_type=VIEW`에 반영한다. `currentPage`, `searchFormState` 및 Excel Manager 설정은 UI에 노출하거나 합치지 않는다.
- 근태 DataTable의 직원 표시는 별도 `employee_name` 가상컬럼을 만들지 않는다. 일별·월별·마감은 물리 `employee_id`, 예외는 물리 `daily_record_id` 컬럼 key를 유지하면서 조회 응답의 직원명을 참조 표시값으로 렌더링하고, 서버 정렬도 해당 물리 key를 직원명 정렬식에 연결한다.
- 일별 근태 DataTable과 TableSettings에는 원본 물리컬럼이 아닌 JOIN `username(아이디)`와 계산 Projection `exception_labels(예외)`를 표시컬럼으로 두지 않는다. 예외 유형 확인은 책임이 분리된 예외 현황 탭에서 수행한다.
- `보기 설정 초기화`는 위 네 VIEW 항목만 공용 기본값으로 되돌리고 `currentPage`와 `searchFormState`를 보존한다. TableSettings 기본값 복원은 기존 TABLE 책임만 유지한다.
- TableSettings는 공용 HTML Grid의 `editorFocusSelectsRow: false` 옵션을 사용한다. 보기 스위치·사용컬럼명·필수구분 편집기 포커스는 순서변경 행 선택을 바꾸지 않으며, 선택열 체크박스를 직접 변경한 경우에만 선택 상태가 변경된다.
- TableSettings의 드래그핸들 열은 header에 `bi-arrows-move`, body에 테두리가 있는 둥근 사각형 `bi-list` 핸들을 사용한다. 표시는 Adapter가 공용 HTML Grid header/editor slot에 주입하고 reorder state는 공용 Grid API를 유지한다.
- TableSettings Grid는 선택 40px, 이동 44px, DB 원본순번 56px, 원본컬럼명 240px, 사용컬럼명 228px, 필수구분 124px, 보기 64px, 너비 136px, 정렬 52px의 공용 기본폭을 사용한다. 전체 984px 폭은 유지하면서 필수구분 Select에 116px을 확보해 `선택안함`과 우측 화살표가 겹치거나 잘리지 않도록 한다. 정렬 열은 28px 공용 아이콘의 중앙정렬 공간을 유지한다. 선택 열은 체크박스 공간만 유지하고 이동·순번·필수구분·보기·정렬 본문은 상하좌우 중앙정렬한다.
- TableSettings 필수구분은 선택된 목록값과 원본컬럼명 우측 별표에서 동일한 색상 의미를 사용한다. `필수`는 danger/red, `선택`은 primary/blue이며 `선택안함`은 기본 글자색과 별표 없음으로 표시한다. 별표는 원본 문자열에 포함하지 않는 렌더링 요소이므로 `table.column` 원본표시와 저장 key 계약을 변경하지 않는다.
- `createDataTableFormSettings`는 공용 TableSettings의 `visibleColumns`, `columnDisplayName`, `columnRequirementPolicy`를 Modal/Form의 물리 필드에 연결한다. 테이블의 `columnOrder`와 사용컬럼명은 실제 목록 순서·Header에 적용하고, 같은 사용컬럼명은 Modal 라벨과 Validation 메시지에도 사용한다. Modal 라벨 오른쪽은 필수 `text-danger` 별표, 선택 `text-primary` 별표, 선택안함은 표시 없음으로 통일하며 필수 정책은 브라우저 저장 검증에도 연결한다. DB `IS_NULLABLE=NO`와 업무조건 필수는 사용자 선택설정으로 약화하거나 숨길 수 없다. 업무조건에 따른 조건부 필수는 정적 TableSettings 정책과 합성하고, 조건부 필수 상태에서는 숨김 설정보다 입력 가능성이 우선한다. 서버 Service도 API 우회가 불가능하도록 동일 업무조건과 사용자 설정 필수정책을 검증해야 한다.
- TABLE 사용자 저장 설정이 존재하면 `visibleColumns`, `columnOrder`, `columnDisplayName`이 실제 DataTable의 표시·순서·Header에 대한 최종 계약이다. 이후 metadata에 추가된 신규 컬럼은 기존 사용자 설정에 자동 노출하지 않고 TableSettings에서 사용자가 명시적으로 켤 때 표시한다. 단, DB·업무상 필수컬럼은 저장 가능성을 위해 계속 강제 노출한다. 참조 Projection은 metadata가 정한 안정 key를 그대로 사용하며 페이지에서 물리 FK key를 다시 덮어써 기존 저장 설정과의 연결을 끊지 않는다.
- TableSettings 저장 후 컬럼 순서·Header 변경으로 DataTable을 재생성할 때는 기존 `<tbody>` DOM 객체를 보존하고 행만 비운 뒤 다시 사용한다. 페이지가 `<tbody>`에 위임한 더블클릭 상세열기·관리버튼 클릭 등 이벤트를 제거하지 않으며, 기존 DataTables API 참조는 재생성된 인스턴스와 동기화한다. 사용자가 기능 복구를 위해 페이지를 수동 새로고침하게 해서는 안 된다.
