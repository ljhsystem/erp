# 회사규모 기간 SSOT 격리 설계

## 실행경계

- Migration 파일, Model·Service 계약, 코드 기반 Matrix Resolver와 회귀계약만 작성했다.
- 운영 Migration, Coverage·회사규모 역사자료 등록, 결재 회수·재계산·재상신·승인은 수행하지 않았다.
- 운영 DB 직접 INSERT·UPDATE는 수행하지 않았다.

## 역사자료 계약

사용자 확인자료는 `MANUAL_CONFIRMED` 또는 `HISTORICAL_IMPORT`로 저장한다. 공식 원문이 없는 자료에 `OFFICIAL_CONFIRMED`를 사용하지 않는다. 근거유형, 근거 ID 또는 설명, 확정 Actor, 확정일시와 산정기준 설명을 보존한다.

2013년 8월 설계 Fixture는 상시근로자 2명, `EMPLOYMENT_INSURANCE_VOCATIONAL`, `LESS_THAN_150`을 사용한다. 이정호는 고용보험 `EXCLUDED`, 박한호는 `APPLICABLE`로 예상한다. 산재보험은 급여 Line을 만들지 않고 별도 업무에서 관리한다.

## 계산 예상

- 기존 사용자부담: 150,960원
- 박한호 고용보험 사용자부담: 6,420원
- 박한호 고용안정·직업능력개발 부담: 2,470원
- 예상 합계: 159,850원

## 운영 적용 전 승인사항

격리 DB에서 실제 MySQL DDL Up/Down, 동시성 기간중복, FK 대상의 운영 스키마 일치, 기존 Line 백필 필요 여부를 재확인한 후 운영 Migration과 역사자료 등록을 별도로 승인해야 한다.

## 운영 적용 결과

- 적용 전 수동 백업: `sukhyang_2026-08-26_113226.sql`
- 운영 적용 Migration: `20260826_01`, `20260826_02`
- 고용보험 Matrix 4개 Revision을 `business_size_code` 기반으로 전환했다.
- 회사규모 기간 Revision 1건과 고용보험 Coverage 2건을 `HISTORICAL_IMPORT`로 등록했다.
- 2013년 8월 급여문서는 공식 회수 Service로 `WITHDRAWN` 처리한 뒤 재계산 금액을 저장했다.
- 저장 금액은 이정호 고용보험 제외, 박한호 근로자부담 6,420원, 사업주 실업급여 부담 6,420원, 직업능력개발 부담 2,470원, 사용자부담 합계 159,850원이다.
- 사후 감사에서 신규 계산 추적 컬럼이 운영 Line에 NULL로 남는 저장계약 이상을 발견했다. 반복 운영 저장은 추가 승인 없이 수행하지 않았다.
- 재상신·결재자 승인 대행은 별도의 명시적 권한이 필요한 고위험 금융 변경으로 차단되어 수행하지 않았다. 증빙·거래 생성은 0건이다.
- 브라우저 런타임은 연결 가능한 브라우저가 없어 수행하지 못했다.

## 저장계약 후속 검증

- PowerShell 기본 디코딩에서 발생한 한글 탐지는 UTF-8 바이트 검사 결과 오탐으로 판정했으며 실제 금지 패턴은 0건이다.
- 계산 추적 9개 컬럼은 `RegularEmploymentIncomeCalculationService::TRACE_COLUMNS`로 단일화했다.
- 급여 저장은 Audit `request_key`와 정규 Payload Hash로 동일 요청을 멱등 반환하고 동일 키의 다른 Payload를 차단한다.
- 임시 MySQL DB의 반복 저장 Fixture에서 동일 키 멱등, 다른 키 무중복 교체, Payload 충돌, 9개 추적 컬럼, 비법정 PAY NULL, 전체 Rollback을 확인했다.
- 임시 MySQL DB의 두 독립 PHP/PDO 프로세스에서 회사규모 중복기간, 동일 요청, 동일 키 Payload 충돌, 동일 이전 Revision 동시 정정을 검증했다. 각 경쟁은 성공 1건 또는 동일 멱등 결과만 남겼고 운영 회사규모·Coverage 건수는 변하지 않았다.
- 운영 재조회 결과 고용보험 등 사회보험 추적값은 정상이나, 기존 저장된 근로소득세·지방소득세 Line의 적용상태와 법정기준 FK가 NULL임을 추가 확인했다. Preview 코드는 이를 보완했지만 이번 단계의 운영문서 반복 재저장 금지에 따라 운영 Line은 변경하지 않았다.
- 인증된 실제 사용자 세션을 구성하거나 결재자를 대행하지 않았고 공식 재상신도 수행하지 않았다.

따라서 현재 판정은 C다. 코드·격리검증은 보완됐지만 기존 운영 세금 Line의 추적정보가 새 계약과 불일치하므로, 별도 운영 재저장 승인 전에는 공식 재상신할 수 없다.
