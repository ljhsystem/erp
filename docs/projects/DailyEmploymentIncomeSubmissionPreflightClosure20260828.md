# 일용근로소득 계산·저장·상신 Preflight Closure

## 확정 범위

- 상태 정책: 저장·수정·삭제·상신 사전검증은 `DRAFT`, `REJECTED`, `WITHDRAWN`만 허용한다. `PENDING`, `APPROVED`는 읽기 전용이다.
- 계산 단위: `Header → Group → Item → Workday → Line`을 재조회해 현재 법정기준으로 재계산하고 각 단계 합계와 법정기준 ID를 대사한다.
- 중복 기준: 같은 회사에서 작업자·근무일·사업구분·프로젝트·작업팀이 모두 같은 활성 문서는 상신 차단 대상이다.
- 비과세: 비과세증감이 0원이 아니면 Workday의 비과세 적용사유를 필수로 대사하며 별도 근거자료 문자열은 요구하지 않는다.
- 보험: `CALCULATED`가 아닌 보험 Preflight는 상신을 차단한다. 보험 적용대상인데 계산정책이 미확정된 경우 0원 확정으로 간주하지 않는다.
- 상용·일용 중복: 직원과 일용 작업자를 연결하는 공식 개인 식별 SSOT가 없으므로 이름 비교로 판정하지 않고 구조화된 경고를 반환한다.
- 상신 버튼: 실제 결재 연결이 없는 회수·결재요청 버튼은 숨김·비활성 상태를 유지한다.

## Migration 적용

운영 DB에는 승인된 `20260827_14_restore_daily_income_group_description`만 적용했다. `institution_daily_employment_income_groups.work_description VARCHAR(500) NOT NULL AFTER work_team_id`와 `ck_daily_income_group_description`만 추가한다. 적용 전 Group 데이터가 0건임을 확인했으며 빈 문자열·공백 문자열 차단과 정상 한글 입력을 트랜잭션 롤백 방식으로 검증했다.

Down은 실행하지 않는다. Down은 대상 Group 데이터가 0건이고 해당 컬럼을 참조하는 런타임을 먼저 중지하거나 되돌린 경우에만 검토할 수 있다.

## 승인 제외와 잔여 경계

- Closure, Accounting Links, Calculation Revision, 비과세 Revision·Audit·Attachment Migration은 적용하지 않았다.
- Evidence Metadata, 결재 문서유형·템플릿, 운영 업무데이터를 생성하지 않았다.
- 현재 source hash는 저장 Aggregate에서 요청 시 계산한다. 별도 Revision 영속화가 필요한 결재 연결 단계는 DB 변경 승인을 받아야 한다.
- Preflight API는 판정만 제공하며 실제 상신·회수·상태변경을 수행하지 않는다.

## 사업구분 상태 및 금액 대사 보강

- 사업구분 공식 저장·정책판정값은 `system_codes.BUSINESS_UNIT.code`이며 화면 표시값은 `code_name`이다. 코드 테이블의 UUID `id`는 Group Payload에 사용하지 않는다.
- 신규 Group에는 공식 기본 사업구분이 없으므로 미선택 상태로 시작한다. Select2 선택은 네이티브 change와 Select2 확정 이벤트 모두 하나의 커밋 흐름으로 수렴하며 Group 상태·DOM dataset·제목·계산/저장 Payload를 동시에 갱신한다.
- 정책 조회 실패는 선택 코드를 지우지 않고 `failed` 상태로 표시한다. 요청 version이 다른 늦은 응답은 현재 선택값을 변경하지 않는다.
- 사업구분 변경 시 프로젝트·작업팀만 초기화하고 Group 작업내용·작업자·공종·작업내용·Workday 입력은 보존한다.
- 금액은 Workday의 단가·과세증감·비과세증감·조정금액만 합산한다. Excel 증감도 첫 실제 Workday에 보이도록 반영하며 화면에 없는 Item 임시 증감을 계산 Payload에 주입하지 않는다.
- 운영 기준정보를 사용한 2026-08 본사 5일×90,000원 검증 결과는 기본지급액 450,000원, 과세증감 0원, 비과세증감 0원, 조정 0원, 소득세 0원, 지방소득세 0원, 근로자부담 보험료 0원, 공제합계 0원, 실지급액 450,000원이다.

## 2013-08 실경로 롤백 검증과 Closure 판정

- 운영 기준정보의 정순옥 작업자를 사용해 2013-08-06부터 2013-08-10까지 매일 480분·90,000원, 증감 0원으로 공식 계산 Service를 실행했다. 각 일자의 기본 지급액·과세금액·총지급액·일용근로소득공제는 각각 90,000원이고 과세표준·산출세액·근로소득세액공제·결정 소득세·지방소득세·보험 근로자부담·기타 공제·공제합계는 0원, 실지급액은 90,000원이다. 5일 합계는 총지급액 450,000원, 공제합계 0원, 실지급액 450,000원이다.
- 화면에 표시됐던 452,940원은 공식 계산 Service에서는 재현되지 않았다. 기존 화면 경로가 Item 임시 과세증감 2,940원을 첫 Workday에 숨겨 주입할 수 있었던 것이 코드상 발생 경로이며, 해당 주입을 제거하고 Workday에 표시된 증감만 계산·저장하도록 통일했다.
- 계산 Service는 일용근로소득공제를 과세금액 이하로 제한하고 과세표준·산출세액·세액공제 후 세액·결정 소득세·지방소득세에 0원 하한을 적용한다. Aggregate는 명시적 환급 Line이 없는 현재 계약에서 공제합계가 음수가 되거나 실지급액이 총지급액을 초과하면 저장을 거부한다.
- 저장·상세·Preflight는 외부 트랜잭션에서 실행한 뒤 롤백했다. 저장 Aggregate와 상세 합계는 450,000원으로 일치했고 Preflight 재계산 source hash도 일치했으며 Header 건수는 실행 전후 모두 0건이다.
- `20260827_18_add_daily_income_actual_work_minutes` 적용 후 실제 근로시간 480분을 Preview·저장·상세·source hash·Preflight·Excel에 연결했다. 신규 Workday는 휴게시간을 제외한 실제 근로 분 1~1,440이 필수이며 동일 근로자·동일 날짜의 문서 전체 Group 합계도 1,440분을 초과할 수 없다.
- 보험사업장 0건·복수 후보, Coverage 0건·중복, 법정기준 누락, 일용 보험료 계산정책 미완성을 보험종류별 구조화 상태로 구분한다. 장기요양보험도 별도 검사하며 미확정 값을 0원으로 확정하지 않는다.
- 보험 판정 Context는 `Workday + 보험종류`다. 사업구분·프로젝트·작업팀은 Workday의 Group에서 상속하고 Coverage는 작업자·보험종류·유효기간으로 판정한다. 보험사업장은 보험종류별로 달라질 수 있으므로 Workday의 단일 `social_insurance_workplace_id`를 모든 보험의 공통 사업장으로 해석하지 않는다. 이를 완전히 영속하는 보험별 결과구조는 다음 별도 승인사항이다.
- 향후 Evidence·거래 생성 Grain은 `문서 + 지급일 + Group + 개별근로자 Item`이다. Group Item 1건당 Evidence 1건과 거래 1건을 생성하고 같은 근로자라도 Group 또는 프로젝트가 다르면 합치지 않는다. 사업구분·프로젝트·작업팀·Group·Item 원본을 보존하며 동일 Group·Item 승인 재시도는 멱등 처리한다. 이번 단계에서는 생성 기능을 구현하지 않는다.
- 현재 운영 DB에는 보험사업장과 정순옥 Coverage가 없고 2013-08 장기요양·산재보험 공식 기준과 적용 보험료 계산정책도 미완성이므로 계산·저장·상신 Preflight Closure는 미확정이며 결재 Lifecycle Closure로 이동하지 않는다.
